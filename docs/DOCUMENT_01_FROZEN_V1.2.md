## 1. Executive decision
CLAUSESHIFT is a token-level cross-lingual semantic difference recognition system. It scores the degree to which every token in one document differs from the corresponding content in another language. The baseline reproduces the paper's LLM few-shot methodology using Apertus. The candidate improvement combines contextual alignment, targeted semantic adjudication and score projection, provided that experiments demonstrate this approach is useful.

**A win requires an actual improvement in macro Spearman**, preferably also credible computational efficiency and an intelligible account of why the method works. Demonstrating a colorful heatmap alone does not meet the principal success criterion.

**Three gating proofs:**
- Model proof: the requested Apertus version actually produced predictions.
- Evaluation proof: the three language-pair Spearman scores were computed by the reference scorer using eligible data and a defensible baseline.
- Reproducibility proof: the code, token order, inference settings and commands reproduce outputs.

**Explicit non-goals:** legal determinations; general-purpose chat; generic RAG; full SaaS platform; training on test; claiming Apertus fine-tuning where none occurred; fictitious performance measurements.

## 2. Official task, dataset, evaluation
The UZH challenge uses SwissGov-RSD, 224 multi-parallel documents, evaluated as EN–DE, EN–FR and EN–IT. Predict a **semantic difference score for each token in both sides**; symmetric disagreements and asymmetric additions/omissions count. The published dataset includes complete splits, but **test must not enter any development operation**.

**Primary metric:** token-level Spearman per language pair, macro-averaged:

`macro = (rho_en_de + rho_en_fr + rho_en_it) / 3`

**Secondary criteria:** computation/efficiency and innovation/creativity. Follow the SwissGov-RSD official scoring script for punctuation (`gold == -1` excluded), preprocessing and ordering. Report Kendall tau-b and per-language runtime as diagnostics; token-level F1 is an optional secondary diagnostic only.

**Baseline:** reproduce a SwissGov-RSD paper method *with Apertus*, choosing the method closer to our proposal. For the initial prompting-driven approach, the paper's three-shot LLM prompting method (Appendix E) is the appropriate starting point. The prompt predicts token **similarity** on 0..5 with punctuation -1; mapped difference `d=1-s/5`, retaining `-1` for punctuation. The project scaffold contains a non-verbatim paper-style example prompt for plumbing tests. **Exact paper baseline status = not verified until Appendix E is supplied verbatim and the real Apertus run succeeds.**

**Predictions:** provide all documents per language in the reference's full-set order, including predictions outside the scored test partition. Outputs must be generated by the submitted code, with no fabricated/padded/truncated values. The official evaluator scores only test at final submission. The encoder-format output shape is `id`, `text_a`, `text_b`, `labels_a`, `labels_b`; the source evaluator uses an unusual `.jsonl.jsonl` suffix for non-LLM-prefixed paths. The strict local validator must run before official scoring.

## 4. Experimental design
- **E0:** Apertus direct few-shot paper baseline (same original prompt, scores and split).
- **E1:** An alignment-only comparator, ideally DiffAlign or a clearly labeled simplified alternative (do not claim DiffAlign reproduction if not identical).
- **E2:** Alignment-guided Apertus correction of semantic differences.
- **E3:** Rank-aware fusion / calibration, tuned only on dev.
- **E4:** Ablation: E2/E3 without Apertus semantic corrections.
- **E5:** Apertus 70B or adapter, only if computational time permits.

**Important:** none of E1–E5 is implemented or benchmarked in the first execution scaffold. Implement them only after a working real E0 baseline. Never describe a mock response as an Apertus result.

**Data protocol:** during development, load or download **only** `gold_labels/dev`. Strip all gold labels before prompting. Protect against accidental use of test/full. After prompt/code freeze, run the final full-set inputs in reference order and score `--split test` once. Public repositories exposing test files are not permission to develop on test.

**Integrity checks:** strict sample ID/order matching, original whitespace tokenization, both-side token counts, score range [-1,1], no missing outputs, deterministic checkpoint order, model identity, recorded prompt hash. Any mismatch blocks export. Keep a frozen Git commit and run metadata.

## 5. Research implementation and architecture

`official DEV input -> input-only JSONL -> 3-shot Apertus -> structured token similarities -> strict parse / map -> predictions JSONL -> official dev evaluator`

Optional follow-up:

`alignment candidates -> targeted Apertus decisions -> bidirectional token scores -> dev-calibrated rank fusion -> independent ablation`

First version uses Python 3.11 stdlib, OpenAI-compatible chat completions, deterministic runs where supported, Docker/Makefile, append-only per-language checkpoints and fail-closed parsing. Run 8B first. Do not add unnecessary services (Kafka, Neo4j, Next.js or orchestration) before gaining a measurable score.

## 6. CSCS 60-second API timeout
Reports from participant Q&A indicate a gateway limit around 60 seconds and HTTP 504 on long requests, including streaming ones. Initial requests have a 52-second timeout. HTTP 504 fails fast (retrying an identically overlong prompt is not a solution). Investigate **declared** decomposition/chunking or self-serving Apertus if required. Do not silently change the baseline prompt while claiming exact reproduction.

### Runtime implications
- 8B first; 70B optional.
- Cap response length explicitly; monitor missing/invalid token outputs.
- Resume completed items without overwriting good outputs.
- Re-run with a new checkpoint directory when changing prompt/model/decoding.
- Avoid using a guessed score for a failed model response.

## 9. Jury narrative
**Pitch (EN):** CLAUSESHIFT uses Apertus to predict how strongly each token in multilingual Swiss government documents differs in meaning across languages. We reproduce the SwissGov-RSD LLM baseline with Apertus and test whether a context-aware, evidence-constrained method improves token-level macro Spearman. The result is open, reproducible and evaluated per EN–DE, EN–FR and EN–IT. All performance claims are supported by the official evaluator; unsuccessful experiments and limitations are documented.

**The scientific claim cannot be filled in ahead of results.** The winning story is a measured gain and a falsifiable account of how Apertus contributed, not the visual design.
